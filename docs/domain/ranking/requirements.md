# 랭킹(Ranking) 도메인 요구사항 명세

> **상태**: v0.3 초안
> **작성일**: 2026-07-13
> **변경 이력**:
> - v0.3 (2026-07-14): 구현 전 상세 검토 반영 — 정합성을 "드문 유실 허용"에서 "유실·중복 없음(원자 멱등)"으로 격상, 삭제 상품은 삭제 사실 전파로 랭킹판에서 제거, 이월 잡 중복 실행 방어 추가.
> - v0.2 (2026-07-14): 주문 신호를 결제 확정 기준으로 명확화 — 결제 미확정 주문은 랭킹에 반영하지 않는다.
> - v0.1 (2026-07-13): 최초 초안. 주문 점수 수량 기준 · 좋아요 취소 감산 · 재전달 시 드문 유실 허용 · 콜드 스타트 이월 포함으로 합의.

---

## 1. 유비쿼터스 언어

| 용어 | 의미 |
|---|---|
| **랭킹판 (Ranking Board)** | 하나의 시간 창 동안 상품별 점수를 누적해 정렬한 집계 단위. 시간 창마다 새로 시작한다. |
| **랭킹 항목 (Ranking Entry)** | 랭킹판 안의 한 줄. 상품 · 점수 · 순위로 구성된다. |
| **행동 신호 (Signal)** | 점수의 원천이 되는 유저 행동. 조회 · 좋아요 · 좋아요 취소 · 주문(결제 확정). 결제가 완료되지 않은 주문은 신호가 아니다. |
| **점수 (Score)** | 행동 신호에 가중치를 곱해 누적한 값. 상품의 상대적 인기를 나타내는 근사값. |
| **가중치 (Weight)** | 행동 신호별 중요도. 조회 0.1 · 좋아요 0.2 · 주문 0.7, 합이 1 이 되도록 설계한다. |
| **순위 (Rank)** | 랭킹판 안에서 점수 내림차순 위치. 1위부터 시작한다. |
| **시간 창 (Time Window)** | 랭킹판이 집계하는 기간. 이번 범위는 일간(하루)이다. 날짜는 Asia/Seoul 기준. |
| **보존 기간** | 랭킹판이 조회 가능하게 유지되는 기간. 시간 창의 2배(2일). |
| **콜드 스타트 (Cold Start)** | 새 시간 창이 시작된 직후 점수가 없어 랭킹판이 비는 문제. |
| **이월 (Carry-Over)** | 콜드 스타트 완화를 위해 전일 점수의 일부를 새 랭킹판에 미리 복사하는 것. |

---

## 2. 유저 스토리

- 사용자는 오늘의 인기 상품 랭킹을 페이지 단위로 조회할 수 있다.
- 사용자는 날짜를 지정해 보존 기간 안의 지난 랭킹을 조회할 수 있다.
- 사용자는 상품 상세에서 그 상품의 오늘 순위를 확인할 수 있다.
- 사용자가 상품을 조회하거나 좋아요를 누르거나 주문을 결제까지 완료하면, 그 행동이 오늘의 랭킹에 반영된다.
- 사용자가 좋아요를 취소하면 오늘의 랭킹 점수에서 그만큼 차감된다.

---

## 3. 기능 요구사항

사용자 관점에서 관찰 가능한 동작만 적는다.

**랭킹 조회**

- 랭킹 조회 시 점수가 높은 순서대로 상품 목록이 페이지 단위로 반환된다.
- 랭킹 항목에는 상품 식별자만이 아니라 상품 이름 · 가격 · 브랜드 · 좋아요 수가 순위 · 점수와 함께 담긴다.
- 날짜를 지정하지 않으면 오늘의 랭킹판을 조회한다.
- 보존 기간을 벗어난 날짜를 지정하면 빈 랭킹이 반환된다.
- 삭제된 상품은 랭킹 목록에 나타나지 않는다.

**상품 상세의 순위**

- 상품 상세 조회 시 그 상품의 오늘 순위가 함께 반환된다. 랭킹판에 없으면 순위는 없음(null)이다.
- 순위를 확인할 수 없는 상황에서도 상품 상세 조회는 정상 동작하고, 순위만 없음으로 반환된다.

**행동 신호 반영**

- 조회 · 좋아요 · 주문 행동은 짧은 지연 안에 그날의 랭킹에 반영된다.
- 주문은 결제가 완료된 시점에, 주문에 담긴 상품별 수량만큼 반영된다. 결제가 실패하거나 완료되지 않은 주문은 랭킹에 반영되지 않는다.
- 좋아요 취소는 오늘의 랭킹 점수에서 좋아요만큼 차감된다.

**콜드 스타트 완화**

- 날짜가 바뀐 직후에도 랭킹이 완전히 비지 않는다 — 전일 인기 상품이 낮은 점수로 미리 올라 있다.

## 4. 유스케이스 흐름

### 4.1 랭킹 페이지 조회

**Main Flow**
1. 사용자가 날짜 · 페이지 · 크기를 지정해(생략 가능) 랭킹 조회를 요청한다.
2. 시스템은 해당 날짜의 랭킹판에서 요청 페이지 구간의 항목을 점수 내림차순으로 가져온다.
3. 시스템은 각 항목에 상품 정보(이름 · 가격 · 브랜드 · 좋아요 수)를 조립한다.
4. 시스템은 순위 · 점수 · 상품 정보가 담긴 목록을 반환한다.

**Alternate Flow — 날짜 미지정** (1 → 1a)
- 1a. 오늘(Asia/Seoul) 랭킹판을 조회 대상으로 한다.

**Alternate Flow — 삭제된 상품 포함** (3 → 3a)
- 3a. 상품 정보를 찾을 수 없는 항목은 목록에서 제외하고 나머지를 반환한다.

**Exception Flow**
- E1 (1): 날짜 형식이 올바르지 않다 → 요청 오류 응답. 상태 영향 없음.
- E2 (2): 해당 날짜의 랭킹판이 없다(보존 기간 초과 또는 집계 이전) → 빈 목록으로 정상 응답. 상태 영향 없음.
- E3 (2): 랭킹판을 조회할 수 없다(집계 저장소 접근 불가) → 조회 실패 오류 응답. 빈 목록으로 위장하지 않는다. 상태 영향 없음.

### 4.2 상품 상세 순위 확인

**Main Flow**
1. 사용자가 상품 상세를 조회한다.
2. 시스템은 상품 상세 정보를 구성한다.
3. 시스템은 오늘의 랭킹판에서 해당 상품의 순위를 확인한다.
4. 시스템은 상세 정보에 순위를 더해 반환한다.

**Alternate Flow — 랭킹판에 없는 상품** (3 → 3a)
- 3a. 순위를 없음(null)으로 한다.

**Exception Flow**
- E1 (2): 상품이 존재하지 않는다 → 상품 없음 오류 응답. 상태 영향 없음.
- E2 (3): 순위를 확인할 수 없다(집계 저장소 접근 불가) → 순위를 없음(null)으로 두고 상세는 정상 반환. 상태 영향 없음.

### 4.3 행동 신호 반영

**Main Flow**
1. 사용자가 상품을 조회하거나, 좋아요를 누르거나, 주문의 결제를 완료한다.
2. 시스템은 행동 사실을 이벤트로 전달한다.
3. 시스템은 이벤트를 받아, 행동이 일어난 날짜의 랭킹판에 가중 점수를 누적한다.
4. 이후의 랭킹 조회에 갱신된 점수가 반영된다.

**Alternate Flow — 좋아요 취소** (3 → 3a)
- 3a. 좋아요 가중치만큼 차감한다. 시간 창을 넘은 취소로 점수가 음수가 될 수 있고, 이는 허용된다.

**Alternate Flow — 주문** (3 → 3b)
- 3b. 결제가 확정된 주문에 담긴 상품별로 수량 × 주문 가중치만큼 누적한다. 결제 전 주문 생성만으로는 아무것도 반영되지 않는다.

**Exception Flow**
- E1 (3): 같은 이벤트가 중복 전달된다 → 이미 처리한 이벤트로 식별해 점수를 다시 누적하지 않는다. 멱등 수렴.
- E2 (3): 점수 반영 도중 장애가 난다 → 처리 표식과 점수 반영은 함께 성공하거나 함께 실패하므로, 실패한 이벤트는 재전달로 다시 처리된다. 유실도 중복도 없다.
- E3 (3): 랭킹판에 반영할 수 없다(집계 저장소 접근 불가) → 랭킹 반영만 미뤄지고, 저장소 복구 후 밀린 이벤트부터 순서대로 따라잡는다(지연, 유실 아님). 행동 자체와 상품 지표 집계는 영향받지 않는다.

### 4.4 새 랭킹판 준비 (콜드 스타트 완화)

**Main Flow**
1. 날짜가 바뀌기 직전(23:50, Asia/Seoul), 시스템은 다음 날 랭킹판을 미리 만든다.
2. 시스템은 전일 랭킹판의 점수에 이월 가중치를 곱해 새 랭킹판에 복사한다.
3. 자정 이후 유입되는 행동 신호는 이월 점수 위에 누적된다.

**Alternate Flow — 전일 랭킹판 없음** (2 → 2a)
- 2a. 복사 없이 빈 랭킹판으로 시작한다.

**Alternate Flow — 다음 날 랭킹판이 이미 존재** (1 → 1a)
- 1a. 아무것도 하지 않는다 — 중복 실행이나 자정 이후 오발동이 이미 쌓인 점수를 덮어쓰지 않도록 방어한다.

**Exception Flow**
- E1 (1~2): 준비 작업이 실패한다 → 다음 날 랭킹은 이월 점수 없이(콜드 스타트 상태로) 시작한다. 행동 신호 반영은 정상 동작하며, 상태 영향은 이월 점수 부재뿐이다. 자정 전 재실행은 허용된다(존재 방어로 멱등).

## 5. 도메인 규칙 / 불변식

- 랭킹판은 시간 창 단위로 분리된다. 서로 다른 날짜의 점수는 섞이지 않는다.
- 행동 신호의 날짜 귀속은 행동이 실제 일어난 시각(Asia/Seoul) 기준이다. 늦게 도착한 이벤트도 행동이 일어난 날의 랭킹판에 반영된다.
- 점수는 행동 신호별 가중치 합산으로 계산된다 — 조회 0.1 · 좋아요 0.2 · 주문 0.7. 주문은 수량 기준이다.
- 주문 신호는 결제 확정 기준이다 — 결제 실패·미결제 이탈 주문은 랭킹 점수를 만들지 않는다. 반영 시점은 주문 생성이 아니라 결제 완료다.
- 가중치는 정책값이며 배포 설정으로 조정될 수 있다. 실시간 조절은 이번 범위 밖이다.
- 좋아요 취소는 좋아요와 대칭으로 차감된다. 시간 창을 넘은 취소로 점수가 음수가 될 수 있고, 이는 허용된다.
- 같은 이벤트는 랭킹 점수에 정확히 한 번 반영된다 — 처리 표식과 점수 반영이 원자적으로 함께 성공하거나 함께 실패하고, 실패는 재전달로 복구된다. 유실도 중복도 없다.
- 랭킹 점수 반영은 상품 지표 집계와 독립된 소비 경로를 갖는다 — 한쪽의 실패·지연이 다른 쪽에 영향을 주지 않는다.
- 상품이 삭제되면 랭킹판에서도 제거된다. 삭제 사실이 전파되기까지의 짧은 시차 동안은 목록 조립에서 걸러진다.
- 순위는 점수 내림차순으로 1위부터 매긴다. 랭킹판에 없는 상품의 순위는 없음(null)이다.
- 랭킹판의 보존 기간은 시간 창의 2배(2일)다. 보존 기간이 지난 랭킹판은 사라진다.
- 이월 점수는 전일 점수에 작은 가중치(기본 10%)를 곱한 값이다 — 이월 점수가 당일 실제 행동을 가리지 않아야 한다.
- 랭킹은 근사값이다. 회계적 정확성이 아니라 상대 순위의 유의미함을 보장한다.
- 점수를 쌓는 쪽과 읽는 쪽은 서로 다른 시스템 구성요소이며, 같은 랭킹판 식별 규약을 공유한다.

> 데이터 구조 결정은 [docs/domain/ranking/logical-model.md](./logical-model.md) 를 참고한다.

## 6. 비기능 요구사항

- 랭킹 조회는 미리 정렬된 집계에서 즉시 응답한다 — 매 요청 원천 데이터를 재집계하지 않으며, 조회 빈도가 높아도 원천 데이터베이스에 부하를 주지 않는다.
- 행동 신호의 랭킹 반영은 실시간에 준한다 — 이벤트 소비 지연만큼(초 단위) 늦을 수 있다.
- 집계 저장소 장애 시의 동작: 상품 상세는 순위 없음으로 정상 동작(폴백), 랭킹 페이지 조회는 오류를 드러낸다, 점수 적재는 지연으로 수렴해 저장소 복구 후 밀린 이벤트부터 따라잡으며 기존 상품 지표 집계에는 영향을 주지 않는다.
- 랭킹 조회는 인증 없이 접근 가능한 공개 지면이다.
- 응답 포맷은 공통 규약(`ApiResponse<T>`)을 따른다. 시간대는 `Asia/Seoul`.
- 랭킹판에는 상품 단위 집계만 담는다 — 유저 식별 정보를 포함하지 않는다.
- 점수 반영의 지연(소비 랙)을 지표로 관측한다 — 반영 실패는 재전달로 복구되므로 유실이 아니라 지연으로 나타난다.
- 페이지 크기 상한 등 조회 파라미터 제약은 기존 상품 목록 조회 규약을 따른다.
